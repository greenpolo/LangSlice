# Tauri GUI Implementation Plan

**Goal:** Replace PySide6 GUI with a Tauri desktop app — Rust backend for atlas ops, React + Three.js frontend, Python subprocess for AI pipeline.

**Repo layout after scaffold:**
```
langslice/          # existing Python package (unchanged)
src/                # React + TypeScript frontend
src-tauri/          # Rust backend + Tauri config
package.json, vite.config.ts, tsconfig.json, tailwind.config.js
```

---

## Phase 1: Foundation + Core Pipeline

Get the full single-image workflow working end-to-end: load atlas → 3D view → load image → run agents → see results in 2D → export.

### 1. Project Scaffold
- `pnpm create tauri-app` with React + TypeScript template
- Add npm deps: `@react-three/fiber`, `@react-three/drei`, `three`, `zustand`, `tailwindcss`
- Add Rust deps in `src-tauri/Cargo.toml`: `ndarray`, `tiff`, `tobj`, `image`, `serde_json`, `rayon`, `base64`, `dirs`
- Add Tauri plugin: `tauri-plugin-dialog` (file open/save)
- Configure `tauri.conf.json`: window size 1400×900, min 1100×720, title "LangSlice"
- Verify `pnpm tauri dev` launches an empty window

### 2. Rust Atlas Loader
- **Types:** `AtlasMetadata` (from `metadata.json`), `AtlasStructure` (from `structures.json`), `AtlasState` (cached volumes + metadata), `MeshData` (vertices + indices + normals)
- **Discovery:** scan `~/.brainglobe/` for `<name>_v<version>/` directories → list available atlases
- **Metadata:** parse `metadata.json` + `structures.json` with serde
- **Volumes:** load `reference.tiff` (multi-page → `Array3<u16>`) and `annotation.tiff` (→ `Array3<u32>`) using `tiff` crate
- **Tauri state:** `AtlasState` wrapped in `Mutex`, managed by Tauri builder
- **Commands:** `list_atlases() → Vec<String>`, `load_atlas(name) → AtlasMetadata`

### 3. Rust Slice Extraction + Borders + Mesh
- **Coronal slice:** index into `reference` volume at AP index → normalize to u8 → encode as base64 PNG
- **Borders:** diff adjacent pixels in `annotation` slice → binary edge map → base64 PNG (same algorithm as Python `_annotation_to_boundaries`)
- **Composite:** blend reference (grayscale) + borders (green #00ff64 at 40% opacity) → RGB base64 PNG
- **Mesh:** parse `meshes/997.obj` (whole brain) with `tobj` → return positions/indices/normals as JSON
- **AP math:** `ap_mm_to_index(mm) → usize`, `index_to_ap_mm(idx) → f64`, `ap_range_mm() → (f64, f64)` — mirrors Python `atlas/core.py`
- **Commands:** `get_coronal_slice(ap_mm) → {reference, borders, composite}`, `get_brain_mesh() → MeshData`

### 4. React App Shell + State + Theme
- **Zustand store:** atlas state, image state, pipeline state (idle/estimating/registering/complete/error), view mode (3d/split/overlay), settings (model, thinking, workflow, landmarks), logs
- **Layout:** header bar + left settings panel + center main area + right agent panel (same 3-column layout as current GUI)
- **Dark theme:** port colors from `langslice/gui/theme.py` — BG `#0a0a0a`, accent `#6366f1`, text `#ededed`
- **Header:** logo, "Open Image" button, "Export" button
- **ViewToolbar:** 3D / Split / Overlay toggle buttons

### 5. 3D Brain Scene
- R3F `<Canvas>` with `<OrbitControls>` (drei)
- **BrainMesh component:** fetch mesh from Rust via `invoke("get_brain_mesh")`, render as semi-transparent wireframe/surface
- **AtlasSlicePlane component:** textured quad positioned at current AP mm, texture from `invoke("get_coronal_slice")`
- Camera default: angled view showing the brain from front-right

### 6. Python Subprocess Integration
- Rust spawns `python -m langslice estimate <image> --atlas <name> --json` using `tokio::process::Command`
- Parse JSON result from stdout (find last `{...}` block in output)
- Then spawns `python -m langslice register <image> --position <mm> --atlas <name> --json`
- Parse registration JSON result
- **Commands:** `run_ap_estimation(image_path, atlas, model, thinking) → APResult`, `run_registration(image_path, position_mm, atlas, ...) → RegistrationResult`
- No streaming progress in Phase 1 — just loading spinner → result

### 7. Settings Panel + Image Loading
- **Settings panel:** atlas dropdown (from `list_atlases`), model dropdown, workflow dropdown, thinking level, landmark count spinner
- **Image loading:** Tauri dialog plugin → file picker → send path to Rust → Rust reads image, returns base64 for display + stores path for pipeline
- Display loaded image in the main area (or 3D scene as a reference)

### 8. Agent Pipeline
- "Run Agent" button → calls `run_ap_estimation` → on success calls `run_registration`
- AgentPanel shows: current step (AP / Registration), status, result summary
- On completion: store AP result + registration result in Zustand, enable 2D views + export
- On error: display error message, reset to idle

### 9. 2D Split View
- Side-by-side: histology slice (left) + atlas reference at estimated AP (right)
- Draw landmark markers (colored circles) on both images using accepted correspondences from registration result
- Match the visual style of current `atlas_viewer.py` split view

### 10. 2D Overlay View
- Atlas composite (reference + borders) overlaid on the transformed histology slice
- Use the same coronal frame geometry as `export.py:compute_coronal_frame_geometry`
- Apply affine transform from registration result to position slice in atlas space
- Opacity slider for atlas overlay

### 11. Export
- "Export" button → Tauri save dialog → call Python `langslice register` export path or implement export in Rust
- For Phase 1: call Python subprocess `python -c "from langslice.export import ..."` with the registration result data
- Output: QUINT/ABBA-compatible JSON file

## Phase 2: Interactivity + Polish

- **AP slider:** manual AP position control, updates atlas slice plane in 3D + 2D views in real-time (Rust reslicing must be fast)
- **Image adjustments:** channel toggles (R/G/B), exposure, brightness, contrast — same controls as current GUI
- **Streaming progress:** replace fire-and-forget subprocess with JSON-lines sidecar protocol for real-time agent logs
- **Atlas region borders toggle**
- **Manual registration mode:** skip AP estimation, use slider position directly

## Phase 3: Dashboard + Multi-Brain

- **Dashboard view:** grid of brain cards with progress bars
- **Multi-slice loading:** drag folder → detect all slice images
- **Multi-agent scheduling:** concurrent AP estimation across slices
- **Navigation:** dashboard → brain detail → back

## Phase 4: Animation + Advanced

- **3D agent animation:** slice planes teleport through brain mesh as agents estimate AP positions
- **Visual state indicators:** searching → converging → locked (color/glow changes)
- **Trace inspector:** port from current GUI for debugging agent behavior
- **Settings dialog:** .env editing for API keys
